# Интерфейс ContentInterface

`ContentInterface` задаёт источник данных для обоих загрузчиков. `MaxMultipartFormUploader` загружает медиафайл
за один запрос, а `MaxUploader` поддерживает возобновление загрузки после прерывания.
Возобновить загрузку после сбоя можно только для перематываемых потоков.

## Готовые реализации

- `Content\FileContent($fileName, $postName = null, $size = null)` — открывает источник через `fopen()` для чтения.
  `$fileName` — путь или адрес источника, который поддерживает `fopen()`; `$postName` — необязательное имя медиафайла
  при загрузке (по умолчанию берётся из `$fileName`); `$size` — необязательный положительный размер в байтах
  (по умолчанию определяется по ресурсу).
- `Content\StringContent($content, $postName)` — загружает строку как медиафайл. `$content` — непустое содержимое
  медиафайла; `$postName` — имя медиафайла при загрузке. Размер вычисляется как число байт строки.
- `Content\StreamContent($resource, $postName, $size = null)` — читает PHP-ресурс потока. `$resource` — открытый ресурс;
  `$postName` — имя медиафайла при загрузке; `$size` — необязательный положительный размер в байтах
  (по умолчанию определяется по ресурсу).

Имя медиафайла — последний сегмент `$postName`. Если `$postName` — ссылка со схемой (`https://…`),
её query (`?…`) отбрасывается. В имени локального файла `?` сохраняется.

При создании с пустым содержимым `StringContent`, `FileContent` и `StreamContent` выбрасывают
`MaxMessenger\Uploader\Exception\StreamException`.
Для `FileContent` и `StreamContent` проверяется размер: переданный `$size` или определённый по ресурсу.

Для неперематываемого источника укажите `$size` при создании `Content\FileContent` или `Content\StreamContent`.
Такой поток можно читать последовательно, но нельзя вернуться к уже прочитанным данным. Загрузка неперематываемого
источника всегда начинается с нуля, даже если передано `setUploadEndpoint($endpoint, false)`. После таймаута
при отправке оба загрузчика повторяют запрос, только если текущий поток перематывается или из него ещё не читали.

## Создание своей реализации ContentInterface

Класс должен реализовать `MaxMessenger\Uploader\Contract\ContentInterface` и возвращать:

- `getSize(): int` — полный размер содержимого в байтах (положительное число).
- `getPostName(): string` — непустое имя медиафайла, которое сервер получит при загрузке.
- `getContentType(): string` — непустой тип содержимого для заголовка `Content-Type`.
- `isSeekable(): bool` — поддерживает ли источник перемотку.
- `getStream(int $offset, int $length, ?Closure $progressCallback): StreamInterface` — поток
  `MaxMessenger\Bot\Contract\Http\StreamInterface` с `$length` байтами, начиная со смещения `$offset`.
  Для реализации можно использовать `HttpClient\Stream\ResourceStream` или  `HttpClient\Stream\StringStream`.

При возобновляемой загрузке `MaxUploader` передаёт в `getStream()` настроенный обработчик `$progressCallback`
или `null`. Если обработчик задан, поток вызывает его после чтения очередной порции, передавая число прочитанных
байт от начала этого потока и его полную длину. Возвращённый поток должен содержать запрошенный фрагмент
длиной `$length` байт. `BaseStream` отслеживает позицию и вызывает обработчик; `ResourceStream` и `StringStream`
реализуют чтение источника. Свой поток может наследовать `BaseStream` или вызывать обработчик при чтении самостоятельно.

`MaxMultipartFormUploader` считает прогресс всей формы отдельно, включая её служебные данные.
